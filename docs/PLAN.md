# GamesTable — план

Личный трекер игр: что прошёл, что хочешь пройти, во что играешь сейчас и что хочешь
просто посмотреть на YouTube или Twitch, не играя. Тот же подход, что в
[FilmTable](https://github.com/mrWD/film-table): без аккаунтов, данные на устройстве.

## Чем это отличается от трекера сериалов

Не косметически, а по существу — и от этого зависит вся конструкция:

**У игры нет эпизодов.** В FilmTable ядро — «следующая непросмотренная серия», и вокруг
неё построено всё. У игры нет естественных единиц прогресса, поэтому центральное действие
другое: **перевод игры между статусами** и, по желанию, часы и оценка.

**Смотреть, а не играть — полноценный сценарий.** Игрофильм или прохождение на YouTube
это отдельный способ «пройти» игру, а не второй сорт. Поэтому «хочу посмотреть» — такой же
статус, как «хочу сыграть», со своей вкладкой и своими ссылками.

**Каталог игр шире одной платформы.** Консольные эксклюзивы не должны быть невидимыми
(см. DATA-SOURCES: у Steam их просто нет).

## Статусы

Две симметричные дорожки — играть и смотреть — плюс «бросил».

| Дорожка | Статусы |
|---|---|
| **Играть** | `backlog` хочу сыграть → `playing` играю → `played` сыграл |
| **Смотреть** | `to-watch` хочу посмотреть → `watching` смотрю → `watched` посмотрел |
| **Прочее** | `dropped` бросил |

Симметрия не для красоты. Игра может ещё не выйти — тогда прохождение только собираешься
посмотреть. А игрофильм на десять часов за один вечер не осилить, и «смотрю сейчас» —
такое же реальное состояние, как «играю сейчас».

`dropped` нужен, иначе брошенное вечно висит в «играю» и врёт в статистике.

## Экраны

1. **Library** — вкладки PLAYING / BACKLOG / PLAYED / WATCH; вкладка WATCH разбита на
   секции «смотрю», «хочу посмотреть» и «посмотрел». Карточка: обложка, название,
   год, платформы, оценка Metacritic, ваша оценка и часы, если проставлены. Действие на
   карточке — быстрый перевод статуса.
2. **Explore** — поиск игр, плюс подборки: популярное, свежие релизы, ближайшие выходы.
3. **Game** — обложка, метаданные, кнопки статусов, личная оценка (1–10), часы, заметка,
   и **ссылки на просмотр**: YouTube (longplay, прохождение, обзор) и Twitch.
4. **Profile** — статистика (сыграно, часов, по платформам и жанрам), экспорт/импорт
   бэкапа, тема, поддержка проекта.

## Как устроен просмотр на YouTube и Twitch

Без API и без ключей: кнопки ведут на готовые поисковые адреса —
`youtube.com/results?search_query=<игра>+longplay` (а также «прохождение» и «обзор») и
`twitch.tv/search?term=<игра>`. Встраивать плеер и запрашивать YouTube Data API не нужно:
для сценария «хочу посмотреть» достаточно попасть в нужную выдачу одним тапом.

## Данные

Библиотека — в `localStorage`, как в FilmTable, с экспортом и импортом JSON. Ничего
личного наружу.

```ts
TrackedGame {
  id: string            // 'rawg:3498' | 'steam:292030' — источник виден по префиксу
  title, cover, released, genres[], platforms[], metacritic
  status: 'backlog' | 'playing' | 'played'
        | 'to-watch' | 'watching' | 'watched' | 'dropped'
  addedAt, startedAt?, finishedAt?
  rating?: number       // 1–10, своя оценка
  hours?: number        // часы, вводятся вручную
  note?: string
}
```

## Источники

Подробности и замеры — в [DATA-SOURCES.md](DATA-SOURCES.md). Кратко: основной каталог —
**RAWG** (бесплатный ключ, все платформы), запасной без ключа — **Steam** (только PC).
Оба идут через тонкий serverless-прокси, потому что Steam не отдаёт CORS, а ключ RAWG
нельзя держать в браузере.

## Стек

Тот же, что доказал себя в FilmTable: React + TypeScript + Vite, zustand с persist,
HashRouter, vite-plugin-pwa, рукописный CSS с токенами тем. Деплой на Vercel: статика и
функция-прокси под одним доменом.

## Что делаем в v1

Библиотека с семью статусами, поиск, страница игры со ссылками на просмотр, профиль со
статистикой и бэкапом, светлая и тёмная темы, PWA. Рекомендации и подборки — после того,
как основное заработает.
